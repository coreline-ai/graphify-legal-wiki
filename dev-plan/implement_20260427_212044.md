## 개발 목적
- `precedent-kr` 124k 노드/761k 엣지 규모에서 Full 3D가 브라우저를 멈추지 않고 전체 형태와 edge 구조를 단계적으로 볼 수 있게 한다.
- raw all-edge 단일 JSON 로딩 대신 cache, worker parsing, LOD/tile, static BufferGeometry, picking 최적화를 조합한다.
- 기존 safe overview UX를 유지하면서 고급 사용자가 점진적으로 edge를 확장할 수 있게 한다.

## 개발 범위
- Backend static spherical layout disk cache를 추가해 124k 노드 좌표 재계산 비용을 줄인다.
- Backend edge tile API를 추가해 전체 edge를 page/tile 단위로 요청할 수 있게 한다.
- Backend binary payload foundation을 추가해 좌표/edge index를 typed-array friendly 형식으로 내려줄 수 있게 한다.
- Frontend Full 3D 요청은 WebWorker fetch/JSON parse 경로를 우선 사용한다.
- Static Three.js renderer의 edge 전용 BufferGeometry 메모리 사용량을 낮춘다.
- Static renderer node picking을 GPU color-picking 방식으로 교체하고 CPU fallback을 유지한다.
- 판례 Full 3D 화면에서 edge tile을 점진적으로 추가하는 버튼/상태를 제공한다.

## 제외 범위
- WebGPU 렌더러 전환.
- 전체 761k edge를 최초 화면에서 자동 로드.
- 서버 사이드 force-directed layout 계산.
- PostgreSQL/pgvector/FTS 판례 검색 인덱스 구현.
- 외부 LLM provider 동작 변경.

## 잔여 리스크 / 후속 과제
- 모든 761,900 edges를 끝까지 로드하는 것은 여전히 사용자가 tile 버튼을 여러 번 눌러 점진 수행해야 한다.
- binary payload는 foundation API만 제공하며, frontend 렌더링 경로는 아직 JSON tile을 사용한다.
- 다음 단계는 binary tile consumer, WebWorker binary decode, tile 자동 백프레셔/메모리 상한 정책이다.
