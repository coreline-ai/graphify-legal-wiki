이 문서는 이번 개발의 범위를 고정하고, 구현이 목적 밖으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적
- `precedent-kr` Full 3D에서 124,263 nodes + 761,900 edges를 더 안정적으로 확장 렌더링하기 위해 현재 객체 기반 edge tile 경로를 typed-array 중심 구조로 전환한다.
- edge tile 요청마다 124k node id 배열을 worker에 반복 전달하는 비용을 제거한다.
- GF3D full node binary를 frontend consumer까지 연결하되, 현재 GF3D header 비대 문제를 해결할 `GF3D-lite` 포맷을 우선 정의한다.
- 자동 tile prefetch는 memory cap/backpressure를 먼저 구축한 뒤 제한적으로 활성화한다.

## 개발 범위
- Persistent graph worker를 도입해 node order/index state를 worker 내부에 보관한다.
- Backend에 `GF3D-lite` node binary endpoint를 추가한다.
- Frontend가 full nodes를 JSON이 아닌 binary로 받아 worker에서 decode한다.
- Static renderer가 `GraphEdgeDTO[]`뿐 아니라 typed-array edge buffers를 직접 받을 수 있게 한다.
- App 상태에 edge tile memory budget, visible edge cap, in-flight cap, optional prefetch 정책을 추가한다.
- 기존 JSON full graph/JSON edge tile 경로는 fallback으로 유지한다.
- 성능 회귀를 막기 위한 unit, API, browser smoke 기준을 추가한다.

## 제외 범위
- WebGPU 렌더러 전환.
- force-directed server layout 계산.
- 판례 검색 DB/pgvector/FTS 인덱스 작업.
- 전체 761,900 edges 자동 일괄 로딩을 기본값으로 활성화.
- source/evidence pane의 법률 자문 관련 UX 변경.

## 문서 기반 제약 사항
- Browser는 raw `graph.json`을 직접 fetch하지 않는다.
- Full 3D Graph는 opt-in, lazy-loaded, safe mode를 기본값으로 유지한다.
- `precedent-kr` raw all-edge는 tile/LOD로만 확장한다.
- `761k+` edges 자동 전체 로드는 실험 모드에서도 memory cap/backpressure 통과 후에만 가능하다.

## 현재 병목 근거
- Full nodes JSON hidden payload: 약 `121MB`, 약 `13.8s`.
- 기존 GF3D binary full nodes: 약 `36MB`, 약 `4.0s`이지만 header JSON이 약 `34MB`로 여전히 큼.
- JSON edge tile 25k: 약 `9.5MB`, 약 `12.9s`.
- Binary edge tile 25k: 약 `0.22MB`, 약 `1.1s`.
- 따라서 다음 병목은 `node metadata/header 비대`, `worker nodeIds 반복 전달`, `GraphEdgeDTO 객체 생성`, `tile 누적 메모리 제한 부재`다.
