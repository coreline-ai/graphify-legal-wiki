# implement_20260425_103546.md

작성 일시: `2026-04-25 10:35:46 KST`

이 문서는 Legal Graph Chat을 “로컬 데모”에서 “운영 배포 가능한 source-grounded legal graph assistant”로 확장하기 위한 후속 개발 범위를 고정한다. 핵심은 coreline-cli Codex auth proxy 기반 LLM 연결, 운영용 auth/private/rate-limit 배포, PostgreSQL 기반 고정밀 판례 검색 인덱스, 전체 그래프 옵션을 유지한 3D 번들 최적화다.

## 개발 목적
- `/answer`의 disabled-by-default LLM scaffold를 실제 외부 LLM provider로 연결하되, 법률 자문이 아닌 source-grounded graph/precedent explanation만 생성한다.
- coreline-cli가 이미 보유한 Codex CLI auth/embedded proxy 구조를 재사용해 Graphify backend가 Codex token을 직접 다루지 않게 한다.
- 운영 배포 시 frontend/backend/source viewer/LLM proxy/PostgreSQL을 private network와 auth proxy 뒤에 배치하고, endpoint별 rate limit을 적용한다.
- `data/precedent-kr` 대형 corpus는 PostgreSQL 중심의 lexical + semantic hybrid index로 전환 준비한다.
- 3D UI는 전체 그래프 옵션을 계속 제공하되, 기본 GUI는 빠르게 로드하고 3D/WebGL 번들은 lazy/code-split한다.

## 개발 범위
- coreline-cli 연동 계획:
  - coreline-cli에 loopback/internal-network 전용 Codex auth proxy server command를 추가한다.
  - Graphify backend는 해당 proxy의 좁은 HTTP contract만 호출한다.
  - Codex auth file/token은 coreline sidecar 내부에만 존재한다.
- Graphify backend:
  - `LLMAnswerProvider` interface와 `CorelineCodexProxyProvider` 추가.
  - `/answer`에서 deterministic fallback + LLM provider 결과를 citation 검증 후 반환.
  - prompt injection/citation validation/timeout/retry/rate-limit 정책 추가.
- 검색 인덱스:
  - PostgreSQL + pgvector(HNSW)를 production target으로 설계한다.
  - keyword/metadata precision은 PostgreSQL FTS + `pg_trgm`, 가능하면 Korean corpus용 PGroonga를 옵션으로 고려한다.
  - SQLite FTS5는 local/dev fallback으로만 유지한다.
- 운영 배포:
  - Docker Compose production profile, nginx auth_request + oauth2-proxy, internal Docker network, rate limit, read-only corpus volume.
  - Codex proxy sidecar는 backend 전용 internal service로 배치한다.
- Frontend/3D:
  - 전체 그래프 tab/option은 유지한다.
  - 기본 GUI는 Chat/Precedents/Subgraph 중심으로 즉시 렌더링한다.
  - `WebGLGraph`, `react-force-graph-3d`, `three`는 tab-level lazy import/manual chunks로 분리한다.

## 제외 범위
- 법률 자문, 승소 가능성 예측, 행동 권고 생성은 계속 제외한다.
- Codex access token을 browser/frontend/API response/log에 노출하지 않는다.
- Graphify Python backend가 `~/.codex/auth.json`을 직접 읽는 방식은 기본 구현에서 제외한다.
- 공용 인터넷에 FastAPI/backend/PostgreSQL/coreline proxy를 직접 노출하지 않는다.
- vector-only 검색으로 전환하지 않는다. 판례/법령 검색은 사건번호, 법원, 선고일자, 법령명 등 exact/metadata ranking을 함께 사용한다.
- 전체 176k edge 그래프를 기본 로드하지 않는다. 전체 edge는 명시적 확인 후 opt-in으로만 유지한다.

## 외부 문서 기반 제약 사항
- Codex CLI는 local terminal에서 동작하는 OpenAI coding agent이며, 첫 실행 시 ChatGPT 계정 또는 API key로 sign-in한다. coreline-cli의 현재 runtime은 이 흐름으로 생성되는 Codex auth를 사용한다.
- OpenAI Codex app-server는 auth/account 상태 확인, 로그인 시작/취소, 로그아웃, rate limit inspection용 JSON-RPC surface를 제공한다. coreline proxy 구현 시 auth 상태/만료/limit 확인 contract를 별도 health로 노출한다.
- Structured Outputs는 JSON Schema 준수를 강제할 수 있으므로 `/answer` LLM 결과는 schema-first로 받고, citation id가 backend evidence set 안에 없으면 폐기한다.
- pgvector HNSW는 IVFFlat보다 speed/recall tradeoff가 좋지만 build time/memory 비용이 크고 approximate recall 특성을 가진다. filter 조건은 사후 적용될 수 있어 `hnsw.ef_search`, iterative scan, btree/partial index를 함께 설계한다.
- PostgreSQL 기본 FTS는 `tsvector`/`tsquery`/rank를 제공하지만 한국어 법률 corpus에는 형태소/공백 한계가 있으므로 PGroonga 또는 trigram 기반 fallback을 함께 평가한다.

## 핵심 아키텍처 결정

| 영역 | 결정 | 이유 | fallback |
|---|---|---|---|
| LLM 연결 | `coreline-codex-proxy` sidecar 우선 | coreline-cli가 Codex auth/Responses 변환 경계를 이미 보유. Graphify가 token을 직접 다루지 않음 | `deterministic` answer 유지 |
| LLM 출력 | strict JSON schema + citation validation | 법률/근거 hallucination 방지 | invalid schema/citation 시 deterministic fallback |
| 배포 | nginx + oauth2-proxy + internal Docker network | auth, private routing, rate limit을 app 밖에서 1차 강제 | localhost-only dev profile |
| 판례 DB | PostgreSQL primary | 3GB+/123k markdown, metadata filter, 운영 백업/권한/인덱스 관리에 적합 | SQLite FTS5 local-only |
| semantic search | pgvector HNSW optional-on | 판례 의미 유사도 검색/answer context 확장 | lexical-only search |
| Korean lexical | PGroonga optional, pg_trgm fallback | Korean corpus exact/substring/fuzzy search 품질 보강 | normalized LIKE/rg fallback |
| 3D | 전체 그래프 옵션 유지 + lazy chunks | 제품 요구 유지, 초기 로드 성능 확보 | 2D/evidence fallback |

## API/contract 초안

### coreline-codex-proxy internal API
- `GET /health`
  - returns `{ ok, auth_mode, account_id_present, model, rate_limit?, warnings[] }`
  - token value는 절대 반환하지 않는다.
- `POST /v1/legal-answer`
  - headers: `Authorization: Bearer <internal shared secret>` 또는 Unix socket/loopback only.
  - request:
    - `question`
    - `instructions`
    - `context_items[]`: `{ id, kind, title, source_path, quote, metadata }`
    - `schema_version`
    - `max_output_tokens`
  - response:
    - `{ answer, citations[], uncertainty, refused, warnings[], raw_usage? }`
  - `citations[].source_id`는 request의 `context_items[].id` 중 하나여야 한다.

## 검색 DB 권고안

| 후보 | 장점 | 단점 | 결정 |
|---|---|---|---|
| current `rg`/filesystem | zero setup, local demo에 충분 | search latency/recall/ranking 제한, 운영 filter/권한/백업 취약 | fallback 유지 |
| SQLite FTS5 | 단일 파일, local-first에 적합 | multi-user/write/index rebuild/semantic 한계 | dev fallback |
| PostgreSQL FTS + pg_trgm | 운영 안정, metadata filter, fuzzy/substring | Korean tokenization 품질 보강 필요 | production lexical baseline |
| PostgreSQL + PGroonga | Korean/CJK full-text에 강함 | extension 운영/복구 고려 필요 | 가능하면 production lexical preferred |
| PostgreSQL + pgvector HNSW | semantic retrieval, metadata와 join 가능 | embedding 비용, approximate recall, HNSW memory/build cost | semantic layer |
| Elasticsearch/OpenSearch | 검색 기능 강력 | 별도 운영 복잡도, Graphify MVP에는 과함 | 현 단계 제외 |

### 권장 ranking pipeline
1. Metadata prefilter: `category`, `court`, `decision_date`, `case_number`, `case_type`.
2. Lexical candidates:
   - PGroonga available: Korean full-text index.
   - 아니면 `pg_trgm` GIN/GiST + normalized title/body/case fields.
   - 기본 PostgreSQL FTS는 보조 rank로 사용.
3. Semantic candidates:
   - `precedent_chunks.embedding` HNSW cosine search.
   - filter가 강할 때는 btree/partial index + `hnsw.ef_search` 조정.
4. Hybrid merge:
   - Reciprocal Rank Fusion 또는 weighted score.
   - exact case number/path/title match는 항상 boost.
5. Answer context pack:
   - top documents에서 source quote를 bounded chars로 추출.
   - citations allowlist 생성.
