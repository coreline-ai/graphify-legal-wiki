# implement_20260425_123622.md

작성 일시: `2026-04-25 12:36:22 KST`

이 문서는 Full 3D Graph의 raw 176k edge를 force simulation 없이 안정 렌더링하기 위한 2차 안정화 범위를 고정한다. 핵심은 backend static 3D layout 좌표 제공, frontend custom Three.js BufferGeometry renderer, 그리고 Vite bundle warning budget 정리다.

## 개발 목적
- `9,001 nodes / 176,128 edges` raw all-edge graph를 브라우저에서 force-directed simulation 없이 렌더링한다.
- Full 3D all-edge는 `react-force-graph-3d` force simulation 대신 static BufferGeometry renderer를 사용한다.
- backend는 deterministic static `x/y/z` 좌표를 제공해 frontend layout 계산/physics 비용을 제거한다.
- Three.js chunk는 lazy 3D chunk로 격리된 상태를 유지하고, Vite warning budget을 명시적으로 조정한다.

## 개발 범위
- Backend:
  - `GraphNodeDTO`에 optional `x/y/z` 추가.
  - `/graph/full-3d`에 `static_layout` query param 추가.
  - Full graph static coordinates를 deterministic하게 계산한다.
- Frontend:
  - `StaticBufferGraph` 컴포넌트 추가.
  - raw/large Full 3D에서는 BufferGeometry `Points + LineSegments`를 사용한다.
  - 기존 3D subgraph/community graph는 현재 WebGLGraph/force renderer 흐름을 유지한다.
  - Full 3D all-edge confirm은 raw 176k edges + static layout 요청으로 전환한다.
- Bundle:
  - Three.js lazy chunk가 의도된 대형 chunk임을 `chunkSizeWarningLimit`로 명시한다.

## 제외 범위
- GPU picking/label full parity는 이번 1차 static renderer 범위에서 제외한다.
- WebWorker binary graph protocol, gzip streaming parser, WASM layout은 제외한다.
- mobile 전용 Full 3D UX는 제외한다.
- backend layout 결과를 디스크 cache로 저장하는 것은 후속 과제로 둔다.

### 남은 리스크 / 후속 개선
- raw all-edge는 force simulation freeze 문제는 제거했지만, JSON payload 자체가 커서 첫 네트워크/parse 비용은 몇 초 발생한다.
- Static renderer는 현재 GPU picking/labels full parity가 없으므로, 후속 Phase에서 color picking 또는 raycast throttling을 검토한다.
- 더 큰 데이터셋에는 backend precomputed layout disk cache, binary payload, worker parsing, 서버 gzip/streaming을 후속 최적화로 권장한다.
