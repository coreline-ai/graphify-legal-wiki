# implement_20260425_115554.md

작성 일시: `2026-04-25 11:55:54 KST`

이 문서는 Legal Graph Chat의 오른쪽 2개 pane, 즉 `Main Workspace`와 `Evidence / Source Inspector` 사이 간격을 사용자가 직접 조절할 수 있게 만드는 개발 범위를 고정하고, 이전 UI 문제였던 3D 그래프 비중앙/탭 텍스트 잘림 문제까지 같은 레이아웃 변경 안에서 재발 방지하기 위한 작업 문서다.

## 개발 목적
- 오른쪽 작업 영역의 두 섹션인 `Main Workspace`와 `Evidence / Source`의 폭을 사용자가 드래그로 조절할 수 있게 한다.
- 3D graph가 현재 pane 실제 크기를 기준으로 렌더링되게 하여, 오른쪽 섹션을 넓혀도/좁혀도 중앙에 보이도록 한다.
- 상단 workspace tab이 좁은 폭에서 잘리거나 화면 밖으로 밀리는 문제를 방지한다.
- 사용자가 조절한 pane 간격을 reload 후에도 유지하되, viewport가 작아지면 안전하게 clamp한다.
- 기존 Obsidian-inspired pane-first UI, source-first 법률 탐색 흐름, Full 3D opt-in/lazy-load 원칙은 유지한다.

## 개발 범위
- Frontend app shell 레이아웃 리팩터링:
  - 현재 `Ribbon + Left Sidebar + Main Workspace + Right Inspector` 구조를 유지한다.
  - `Main Workspace`와 `Evidence / Source Inspector` 사이에 vertical resize handle을 추가한다.
  - 사용자가 조절 가능한 CSS custom property 또는 React state 기반 pane width contract를 정의한다.
- 사용자 조절 기능:
  - pointer drag 기반 폭 조절.
  - keyboard 접근성: `role="separator"`, `aria-orientation="vertical"`, `tabIndex`, Arrow/Home/End/Enter reset 지원.
  - 최소/최대 폭 clamp 및 viewport resize 대응.
- 상태 저장:
  - `localStorage`에 pane layout preference 저장.
  - 저장된 값이 현재 viewport에서 불가능하면 자동 보정한다.
- 3D 그래프 크기 계산 수정:
  - `WebGLGraph`는 `window.innerWidth - 460` 같은 전역 추정값 대신 container 실제 크기를 사용한다.
  - resize 후 `ForceGraph3D` canvas width/height가 즉시 맞춰지고 필요 시 `zoomToFit()`을 debounce 호출한다.
  - 2D fallback SVG도 container 안에서 어긋나지 않도록 보정한다.
- 탭 overflow 보정:
  - `.lg-tabbar`는 좁은 pane에서 `overflow-x: auto`, `white-space: nowrap`, shrink-safe 스타일을 갖는다.
  - 긴 탭명은 접근성을 유지하면서 작은 폭에서 truncate 또는 compact label 정책을 적용한다.
- 테스트/검증:
  - layout clamp/storage helper 단위 테스트.
  - frontend test/build.
  - browser smoke로 1440x900, 1280x800, 1024x768에서 drag/reload/keyboard/3D centering 확인.

## 제외 범위
- Backend API, LLM provider, Codex auth proxy, precedent index, PostgreSQL/pgvector 작업은 수정하지 않는다.
- `graph.json` 또는 graph 데이터 구조를 변경하지 않는다.
- 전체 3D graph의 기본 로드 정책을 바꾸지 않는다. Full 3D는 계속 opt-in/lazy-load다.
- 왼쪽 ribbon/left sidebar의 사용자 조절 기능은 이번 범위에 포함하지 않는다.
- 대규모 디자인 리브랜딩, 색상 시스템 재설계, Obsidian 상표/자산 사용은 포함하지 않는다.
- 모바일 전용 drawer/reflow 재설계는 하지 않는다. 단, 작은 desktop viewport에서 깨지지 않도록 clamp만 보장한다.

## 확정 수정 방향
- 단순히 `--lg-right-sidebar-width`를 키우는 방식은 채택하지 않는다. 고정폭을 늘리면 다른 viewport에서 workspace가 더 좁아지고, 3D canvas 비중앙 문제도 남기 때문이다.
- `Main Workspace`와 `Evidence / Source Inspector`를 하나의 resizable right-side pane group으로 보고, 사용자가 divider를 움직여 두 pane의 비율을 바꾸게 한다.
- 기본 레이아웃은 3D/Chat이 들어가는 `Main Workspace` 가독성을 우선한다. `Evidence / Source Inspector`는 현재 360px보다 약간 넓어질 수 있지만, workspace 최소 가용폭을 침범하지 않는다.
- 3D 렌더러 수정은 필수다. splitter만 구현하고 `WebGLGraph`의 `window.innerWidth - 460` 계산을 남기면 graph center가 다시 틀어진다.
- tabbar 수정도 필수다. pane resize로 workspace가 좁아질 수 있으므로 탭은 줄바꿈보다 horizontal scroll/nowrap을 기본 정책으로 한다.
- 구현 후 완료 판정은 “드래그 가능”이 아니라 `드래그 + 키보드 + 저장/복원 + 3D 중앙 + 탭 접근 + viewport clamp` 전체가 통과해야 한다.

## Layout contract 초안
- 사용자가 말한 “오른쪽 2개 섹션”은 현재 코드 기준 다음 두 pane으로 정의한다.
  - `Main Workspace`: Chat / Precedents / 3D Subgraph / Community Overview / Full 3D / Verify.
  - `Evidence / Source Inspector`: selected evidence, source preview, community/wiki actions.
- app shell grid 후보:

```css
.lg-app-shell {
  grid-template-columns:
    var(--lg-ribbon-width)
    var(--lg-left-sidebar-width)
    minmax(0, 1fr)
    var(--lg-pane-splitter-width)
    var(--lg-inspector-width);
}

.lg-tabbar,
.lg-main-workspace { grid-column: 3; }
.lg-pane-resizer { grid-column: 4; grid-row: 1 / span 2; }
.lg-inspector { grid-column: 5; grid-row: 1 / span 2; }
.lg-statusbar { grid-column: 2 / -1; }
```

- 권장 기본값은 `workspace-first`로 확정한다.
  - splitter width: `6px`; pointer hit area: `10~12px`.
  - wide viewport 기본: inspector는 `360~420px` 사이에서 시작하되 workspace가 충분히 남을 때만 420px에 가까워진다.
  - 1440px viewport 기준 목표: workspace는 기존 744px보다 작아지지 않도록 우선 보장하고, inspector는 약 `370~400px` 범위에서 시작한다.
  - 사용자가 직접 드래그하면 inspector는 더 넓어질 수 있지만 workspace minimum 이하로는 내려가지 않는다.
- viewport tier별 clamp 후보:

| tier | 조건 | workspace 최소 | inspector 최소 | inspector 최대 | 정책 |
|---|---:|---:|---:|---:|---|
| wide | `>= 1360px` | `720px` | `320px` | `520px` | 3D/Chat workspace 우선, inspector 확장 허용 |
| desktop | `1200~1359px` | `640px` | `300px` | `460px` | 탭 scroll 가능, source preview 유지 |
| compact | `1024~1199px` | `420px` | `260px` | `380px` | 탭 horizontal scroll 필수, inspector는 보존하되 좁힘 |
| below target | `< 1024px` | best effort | best effort | best effort | 이번 범위의 전용 모바일 재설계는 제외, 깨짐 방지 clamp만 적용 |

- 저장 schema 후보:

```ts
type PaneLayoutPreferenceV1 = {
  version: 1;
  inspectorWidth: number;
  savedAt: string;
};
```

- localStorage key 후보: `legal-graph-chat:pane-layout:v1`.
- pointer resize 계산 기준:
  - handle이 `Main Workspace`와 `Inspector` 사이에 있으므로 drag right는 inspector를 줄이고 workspace를 넓힌다.
  - drag left는 inspector를 넓히고 workspace를 줄인다.
  - 최종 width는 항상 `getPaneBounds(containerWidth)` 결과로 clamp한다.
- reset 기준:
  - double click 또는 Enter는 viewport tier의 default inspector width로 복원한다.

## 3D / tabbar 완료 판정 기준
- `WebGLGraph.tsx` 내부에서 renderer width/height 계산에 `window.innerWidth - ...` 형태의 전역 추정값이 남아 있지 않아야 한다.
- `ForceGraph3D`의 `width`와 `height`는 `.lg-webgl-canvas` 또는 상위 viewport의 `ResizeObserver` 실측값을 사용해야 한다.
- splitter drag 직후 canvas DOM 크기와 pane client size 차이가 허용 오차 2px 이내여야 한다.
- resize 후 graph가 한쪽으로 밀려 보이면 `zoomToFit()`/camera fit debounce 또는 renderer refresh를 적용한다.
- `.lg-tabbar`는 좁은 workspace에서도 모든 tab button이 keyboard focus와 horizontal scroll로 접근 가능해야 한다.
- active tab 변경 시 필요하면 `scrollIntoView({ inline: 'nearest' })`를 사용해 선택 탭이 보이게 한다.

## 구현 준비 메모
- 가장 안전한 구현 순서는 `layout helper → App shell splitter → WebGLGraph container size → tabbar overflow → QA`다.
- `WebGLGraph` 크기 문제는 splitter와 별개로 반드시 같이 수정해야 한다. 그렇지 않으면 사용자가 workspace를 넓혀도 3D canvas가 전역 viewport 기준으로 계산되어 다시 어긋날 수 있다.
- drag 구현은 DOM 이벤트 cleanup 누락 시 memory leak/ghost drag가 생길 수 있으므로 `pointercapture` 또는 window listener cleanup을 Phase 5에서 반드시 검증한다.
- CSS grid 변경 시 `footer.lg-statusbar`의 `grid-column` 범위가 splitter column까지 포함하는지 확인한다.
- 구현 후에는 backend/coreline 테스트까지 전부 돌릴 필요는 없지만, frontend build/test와 browser smoke는 필수다.
