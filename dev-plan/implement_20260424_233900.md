## 문서 기반 제약 사항
- graphify 파이프라인은 `detect → extract → build_graph → cluster → analyze → report → export` 순서로 진행한다.
- 문서/법령 Markdown semantic extraction은 assistant/model API 비용과 시간이 발생할 수 있다.
- README 기준 clustering은 embedding/vector DB가 아니라 graph topology 기반이다.
- code AST extraction과 달리 Markdown semantic extraction은 파일 내용이 provider model API로 전달될 수 있다.
- 기본 Python `3.14`는 `pyproject.toml`의 `<3.14` 요구사항과 맞지 않으므로 `python3.11` 또는 uv 격리 환경을 사용한다.
- graphify skill의 semantic extraction 단계는 파일을 20~25개 단위 chunk로 나누고 subagent를 병렬 dispatch하는 구조다. `data/legalize-kr` 5,665개 기준 예상 chunk/subagent 수는 약 `230~284`개다.
- Codex에서 subagent 병렬 처리를 사용하려면 `~/.codex/config.toml`에 `multi_agent = true` 설정이 필요할 수 있다.
