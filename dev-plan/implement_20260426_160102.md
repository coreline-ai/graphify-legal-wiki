# implement_20260426_160102.md

작성 일시: `2026-04-26 16:01:02 KST`

이 문서는 Legal Graph Chat의 `Full 3D Graph`가 사용자가 기대한 “원형/구형 3D 전체 그래프”가 아니라 대각선 block/arc/직사각형 slab처럼 보이는 현상을 현재 구현 방식 기준으로 고찰하고, 원형/구형 레이아웃으로 수정하기 위한 범위를 고정한다.

> 2026-04-26 16:32 KST 추가 정정: 1차 `circular` annulus 수정은 평면 원반에 가까워 사용자가 기대한 “원래 3D 원형 노드-엣지 hairball”과 달랐다. 따라서 기본 Full 3D는 `spherical` static layout으로 재수정한다. `circular`는 비교용/후퇴용으로 보존하되 기본값에서 제외한다.

## 개발 목적
- `Full 3D Graph` safe overview와 raw all-edge static view가 원형 3D cloud/hairball처럼 인지되도록 만든다.
- 현재 static renderer의 장점인 freeze 방지, force simulation off, lazy-load, source-first 탐색 원칙은 유지한다.
- 현재 방식의 문제를 “색/카메라값 튜닝”으로만 덮지 않고, backend layout contract와 frontend rendering intent를 함께 고친다.
- 구현 전/후를 Playwright screenshot과 layout 수치로 비교 가능하게 만든다.

## 개발 범위
- Backend `/graph/full-3d` static layout 개선:
  - 기존 `static_layout=true` 경로에 원형 레이아웃 모드를 추가한다.
  - community cluster ring 방식과 원형 full graph 방식의 의도를 분리한다.
  - node `x/y/z` 좌표는 계속 deterministic하게 생성한다.
- Frontend Full 3D 요청/표시 개선:
  - Full 3D는 기본적으로 spherical static layout을 요청한다.
  - UI copy/chip/status에 현재 layout mode를 명시한다.
  - raw all-edge는 기존처럼 static BufferGeometry renderer에서만 처리한다.
- Visual QA:
  - hidden safe overview와 raw 176k all-edge view를 screenshot으로 검증한다.
  - console warning/error, API latency, payload count를 함께 기록한다.
- 문서/테스트:
  - backend layout 단위 테스트와 frontend static renderer smoke 기준을 추가한다.
  - README/frontend README/계획 문서를 실제 동작과 맞춘다.

## 제외 범위
- raw 176,128 edge를 `react-force-graph-3d` force simulation에 다시 넣지 않는다.
- WebWorker parsing, binary payload, streaming protocol 전환은 이번 원형 layout 수정의 직접 범위에서 제외한다.
- GPU picking/label full parity는 후속 과제로 둔다.
- 법령 그래프 데이터 자체(`graph.json`)를 재생성하거나 community detection 결과를 바꾸지 않는다.

### 현재 layout 알고리즘
- backend는 community별로 node를 그룹화한다.
- community center는 `center_radius=560`의 X/Z ring 위에 균등 각도로 배치된다.
- community 내부 node는 golden-angle spiral로 배치된다.
- 큰 community는 `shell_scale`이 `260`으로 clamp되어 대부분의 node가 community 내부 외곽 원반/껍질에 몰린다.
- Y축은 community index 기반 offset과 degree 기반 `hub_lift`가 섞인다.
- frontend는 전체를 bounds center로 정규화하고 oblique camera/rotation으로 보여준다.

## Root cause 확정
- 현재 방식은 “전체 원형 graph”가 아니라 “community cluster들을 큰 ring 위에 올린 grouped-cluster layout”이다.
- community 수가 12개라 center는 원형이지만, node는 각 center 주변의 큰 disk/cloud에 들어가므로 전체 실루엣이 하나의 circle로 보이지 않는다.
- 큰 community의 local radius가 `260`으로 포화되어 node cloud가 넓은 블록처럼 보인다.
- community 크기가 매우 불균형한데 center angle은 균등 분할이라, 큰 community가 화면 일부를 과점하고 작은 community는 점/작은 cloud로 보인다.
- raw all-edge의 cross-community edge가 `92,516`개라 cluster 사이를 메우는 line overdraw가 직사각형 면처럼 보인다.
- oblique camera는 이전 “납작한 회색 slab” 문제를 완화했지만, 원형성이 아니라 3D 깊이를 강조하는 방향이어서 현재 “원형이 아님” 문제의 본질을 해결하지 못한다.

## 수정 방향

### 핵심 결정
- `Full 3D Graph`의 기본 static layout은 `circular_full`로 분리한다.
- 기존 community-cluster 방식은 `community_cluster` 또는 `clustered` layout mode로 보존한다.
- raw all-edge도 `circular_full` 좌표를 사용해 edge가 원형 chord/density haze로 보이도록 한다.
- force-directed layout은 대형 raw graph에 재도입하지 않는다.

### 제안 API contract
- `/graph/full-3d` query param 추가:
  - `static_layout_mode=clustered|circular`
  - 기본값은 backend compatibility를 위해 `clustered`로 둘 수 있다.
  - frontend Full 3D에서는 명시적으로 `static_layout_mode=circular`를 요청한다.
- `GraphPayloadDTO`에 optional `layout_mode` 또는 warning/status metadata를 추가할지 검토한다.
  - 최소 변경안: warnings/status copy에 layout mode 포함.
  - 명확한 계약안: `GraphPayloadDTO.layout_mode?: string` 추가와 contract snapshot 업데이트.

### 제안 circular layout 알고리즘
- community별 node 수에 비례해 전체 원 둘레의 angular wedge를 배정한다.
- node는 `community → degree desc → label/id` 순으로 deterministic 정렬한다.
- 각 community wedge 안에서 node를 여러 concentric ring에 배치한다.
- radius는 global annulus 기준으로 제한한다.
  - 예: `inner_radius=260`, `outer_radius=780`.
  - 큰 community도 disk cluster가 아니라 wedge/annulus로 펴진다.
- Z 또는 Y depth는 원형 실루엣을 해치지 않는 작은 값으로 제한한다.
  - degree/hub lift는 유지하되 `±120` 수준으로 clamp한다.
  - 또는 `z = sin(theta) * radius`, `x = cos(theta) * radius`, `y = bounded depth/lift`로 circular shell 유지.
- community 사이에는 작은 angular gap을 둬 색상 구역을 읽을 수 있게 한다.
- isolated/small community는 minimum wedge를 보장한다.
- raw all-edge는 edge opacity 현재 정책을 유지하되, circular chord처럼 보이도록 edge endpoints 자체를 annulus에 배치한다.

## 1차 circular 구현 결과 (2026-04-26 16:16 KST, Phase 6에서 superseded)

### 왜 바뀌었는가
- `2026-04-25 12:22~13:04 KST` 사이 Full 3D는 raw `176,128` edge force simulation freeze를 피하기 위해 `react-force-graph-3d` 중심 경로에서 backend static `x/y/z` + frontend `BufferGeometry` 경로로 의도적으로 전환됐다.
- 이전 force 방식은 브라우저가 자연스럽게 hairball을 풀어 원형/구형처럼 보였지만, 대형 graph에서는 main thread/GPU freeze 위험이 컸다.
- 현재 clustered static 방식은 freeze를 제거했지만 community center만 ring이고 node cloud는 community별 disk라, 전체가 원형이 아니라 block/slab처럼 보였다.

### 적용한 알고리즘
- 당시 `static_layout_mode=clustered|circular` API contract를 추가했다.
- 당시 backend 기본값은 호환성을 위해 `clustered`로 유지하고, frontend Full 3D는 `circular`를 명시적으로 요청했다.
- circular layout은 community size proportional wedge + minimum wedge/gap + degree-desc deterministic ordering + concentric annulus rings를 사용한다.
- 좌표는 `x=cos(theta)*radius`, `z=sin(theta)*radius`, `y=bounded lift/wave`로 생성해 raw edge가 직사각형 slab이 아니라 원형 chord/density haze로 보이게 했다.
- 기존 clustered layout은 비교/분석용으로 보존했다.

## 잔여 리스크 / 후속 과제
- 원형 layout은 가독성/미학 목적의 deterministic static projection이며, graph topology 최적화 layout은 아니다.
- raw 176k edge는 어떤 layout에서도 hairball 특성이 남는다. 개별 관계 해석은 focus/subgraph/evidence view가 정답이다.
- circular layout이 cluster 내부 연결성을 덜 강조할 수 있으므로 `clustered` 모드는 비교/후속 분석용으로 보존하는 것이 안전하다.
- payload parse/main-thread block은 여전히 남을 수 있으며, WebWorker parsing과 layout disk cache는 별도 성능 Phase로 진행하는 것이 맞다.

## Phase 6. circular annulus 피드백 반영: 원래 3D spherical hairball 복원

### 사용자 재피드백
- “갈 수록 이상해지는데? 원래 형식 3D로 만들어 원형에 노드와 엣지가 연결된 형태로”
- 해석: 사용자가 기대한 것은 평면 annulus/2D circular chart가 아니라, 이전 force graph처럼 둥근 3D 공간 안에 node와 edge가 연결된 spherical hairball이다.

### 원인 보정
- 1차 수정의 `circular` layout은 원형성은 확보했지만 `y` depth가 제한된 annulus라 “3D 구형 graph”가 아니라 “평면 원반/구간형 chart”로 인지될 수 있었다.
- 특히 `2D fallback` 탭에서는 backend `x/y` projection을 그대로 사용하므로 rectangular/flat view처럼 보일 수 있다.
- 따라서 Full 3D 기본은 `circular`가 아니라 `spherical`이어야 한다.

### 적용한 수정
- `static_layout_mode=clustered|circular|spherical`로 contract 확장.
- `apps/legal-graph-chat/backend/app/service.py`
  - `_full_graph_spherical_positions(nodes)` 추가.
  - community별 broad latitude/longitude band + Fibonacci/golden-angle scatter를 사용.
  - 모든 node에 실제 `x/y/z` depth를 부여하고, edge는 sphere 내부 chord로 연결되게 함.
- `apps/legal-graph-chat/backend/app/main.py`
  - 직접 API 호출도 `static_layout_mode` 생략 시 `spherical`이 되도록 backend default를 변경.
- `apps/legal-graph-chat/frontend/src/App.tsx`
  - Full 3D 기본 요청값을 `spherical`로 변경.
  - safe/raw copy를 `spherical 3D layout`으로 수정.
- `apps/legal-graph-chat/frontend/src/components/WebGLGraph.tsx`
  - `layout spherical 3D` chip 표시.
- `apps/legal-graph-chat/frontend/src/components/StaticBufferGraph.tsx`
  - `spherical 3D layout` status chip 표시.
- `apps/legal-graph-chat/frontend/src/utils/staticGraphRenderer.ts`
  - `circular`만 top-down flat camera를 쓰고, `spherical`은 oblique 3D camera/rotation을 사용.
- `apps/legal-graph-chat/frontend/src/components/WebGLGraph.tsx`
  - Full 3D payload 변경 시 사용자가 이전에 `2D` fallback을 열어둔 상태여도 static 3D renderer로 자동 복귀하도록 보정했다.
- `apps/legal-graph-chat/backend/README.md`
  - backend `static_layout_mode` 기본값 문서를 `spherical`로 정정했다.

### 성능 알고리즘 결정
- raw 176,128 edge에는 force simulation을 재도입하지 않는다.
- 최고 성능 경로는 `backend deterministic spherical coordinates + frontend Three.js BufferGeometry Points/LineSegments`다.
- 이유:
  - 좌표 계산은 O(N), edge buffer 생성은 O(E)로 단순하다.
  - physics tick이 없어 frame-to-frame 비용이 낮다.
  - payload와 좌표가 deterministic해 screenshot/테스트/캐시가 쉽다.
  - 176k edge를 GPU line segment buffer로 넘겨 force graph보다 freeze 위험이 낮다.

## Phase 7. 2D fallback projection 원형 깨짐/한쪽 쏠림 수정

### 사용자 재피드백
- “2D 그래프를 보라고 원형이 아니잖아. 한쪽으로 뭔가 치우쳤다.”

### root cause 확정
- `apps/legal-graph-chat/frontend/src/utils/graphLayout.ts`의 2D fallback이 backend static world coordinate를 SVG pixel coordinate처럼 직접 사용했다.
- backend spherical 좌표는 대략 `-720~720` 범위인데, 2D fallback은 이를 `0~980 / 0~580` pixel로 해석하고 `24px` 경계로 clamp했다.
- 결과적으로 음수 좌표는 한쪽 경계에 눌리고, 큰 좌표는 반대쪽 경계에 눌려 “원형”이 아니라 치우친 slab/덩어리처럼 보였다.
- 추가로 기존 spherical algorithm의 community latitude band가 X/Z 2D projection 중앙을 비워 donut처럼 보이게 했다.

### 적용한 수정
- `apps/legal-graph-chat/frontend/src/utils/graphLayout.ts`
  - static `x/y/z`가 있으면 raw pixel로 쓰지 않고 world coordinate를 SVG viewport에 uniform scale로 fit한다.
  - 2D fallback은 3D graph의 수평면인 `x/z`를 projection 축으로 사용한다.
  - 중심 정렬과 동일 scale을 적용해 원형이 타원/한쪽 clamped shape로 찌그러지지 않게 했다.
- `apps/legal-graph-chat/backend/app/service.py`
  - spherical layout이 community별 좁은 latitude band에 갇히지 않고 full polar axis를 사용하도록 수정했다.
  - X/Z projection도 중앙이 비지 않는 filled circle이 되도록 보정했다.
- `apps/legal-graph-chat/frontend/src/utils/graphLayout.test.ts`
  - backend 3D static 좌표가 2D에서 centered circle로 투영되는 회귀 테스트 추가.
- `apps/legal-graph-chat/backend/tests/test_service.py`
  - spherical layout의 X/Z projection이 중심부와 외곽을 모두 커버하는 회귀 테스트 추가.

- “2D의 경우 클릭 하면 화면이 번쩍 번쩍 거려 원인 분석 하고 수정 해줘”

### root cause 확정
- 대형 2D Canvas renderer가 node 선택 변경마다 `useEffect`에서 다시 그렸다.
- draw effect가 매번 `canvas.width`/`canvas.height`를 대입했는데, canvas backing store width/height 대입은 같은 값이어도 bitmap을 초기화한다.
- React paint 이후 effect redraw + backing store reset + 5,000 link redraw가 겹쳐 클릭 시 빈 canvas/깜빡임처럼 보일 수 있었다.
- 같은 node를 다시 클릭해도 `loadNodeExplain`이 반복 호출되어 불필요한 async state update와 redraw가 발생했다.
- 3D의 5,000개는 hard limit이 아니라 기본 safe overview의 sampled edge limit이다. raw 176,128 edges는 별도 확인 버튼으로 유지한다.

### 적용한 수정
- `apps/legal-graph-chat/frontend/src/components/GraphFallback.tsx`
  - Canvas redraw를 `useEffect`에서 `useLayoutEffect`로 변경해 paint 전에 동기 redraw한다.
  - 같은 node 재선택은 no-op 처리해 불필요한 `/explain` 재요청과 redraw를 막는다.
- `apps/legal-graph-chat/frontend/src/utils/canvas2dRenderer.ts`
  - canvas backing store 크기가 실제로 달라질 때만 width/height를 대입하는 helper 추가.
  - DPR은 2로 cap해 대형 graph redraw 비용을 제한한다.
- `apps/legal-graph-chat/frontend/src/utils/canvas2dRenderer.test.ts`
  - 같은 backing store 크기에서는 width/height setter가 호출되지 않는 회귀 테스트 추가.

### 검증 결과
- Frontend: `npm run typecheck && npm run test && npm run build` → 통과 (`4 files / 20 tests passed`)
- Browser Full 3D safe overview: `1,500 nodes / 5,000 edges / layout spherical` 로드 확인.
- Browser 2D Canvas click 2회: selected node/inspector 갱신 유지, console warning/error `0`.
- Screenshot: `output/playwright/full3d-2d-click-no-flash.png`

### 최종 상태
- 2D Canvas 클릭 시 canvas bitmap을 매번 강제 초기화하지 않는다.
- 선택 highlight만 필요한 redraw는 paint 전에 수행되어 번쩍임을 줄인다.
- 3D 5,000 edge는 기본 안전 샘플이다. raw 176,128 edge path는 `Raw 176k all-edge 로드`로 유지한다.

## Phase 12. 2D/3D click flicker 재조사와 canvas/WebGL remount 제거

### 사용자 재피드백
- “여전히 클릭하면 번쩍거려 2D, 3D 모두 상세 원인 분석 하고 이번에 제대로 고쳐봐”

### root cause 확정
- Phase 11은 2D Canvas backing store reset만 막았지만, click 후 React parent state가 바뀌면서 3D static renderer 쪽에 더 큰 remount 경로가 남아 있었다.
- 3D `StaticBufferGraph`는 `selectedNodeId`와 inline `onSelectNode`를 scene mount effect dependency에 포함했다.
  - Full 3D node click → `loadNodeExplain` → App state update.
  - App의 inline callback identity 변경 + `selectedNodeId` 변경.
  - `StaticBufferGraph` effect cleanup 실행.
  - cleanup에서 `container.replaceChildren()`로 WebGL canvas 제거.
  - 다시 Three scene/BufferGeometry/renderer 생성.
  - 이 제거/재생성 과정이 3D click flash의 직접 원인이었다.
- 2D는 같은 backing store reset은 줄었지만, 선택 highlight를 base graph와 같은 canvas에 그려 selection 변경 때마다 5,000 edges + 1,500 nodes 전체를 다시 그렸다.
  - 클릭 시 필요한 작업은 선택 ring 1개 갱신뿐인데 base graph 전체를 clear/redraw 하는 구조였다.
  - 사용자가 보는 “번쩍”을 없애려면 base canvas는 고정하고 selection overlay만 갱신해야 한다.
- 공통적으로 “선택 상태 변경”이 “대형 그래프 전체 renderer 갱신”으로 전파된 것이 문제였다.

### 적용한 수정
- `apps/legal-graph-chat/frontend/src/components/StaticBufferGraph.tsx`
  - Three scene mount effect에서 `selectedNodeId`/`onSelectNode` dependency 제거.
  - 최신 callback/selected id는 ref로 유지.
  - selected highlight point를 scene 생성 시 1회 만들고, 선택 변경 시 `BufferAttribute` position만 업데이트.
  - node 재클릭은 no-op 처리해 불필요한 `/explain` 재호출을 차단.
  - 결과: 3D click은 더 이상 WebGL canvas를 제거/재생성하지 않는다.
- `apps/legal-graph-chat/frontend/src/components/GraphFallback.tsx`
  - 대형 2D Canvas를 base canvas + selection overlay canvas 2장 구조로 분리.
  - base graph는 `layout` 변경 때만 그림.
  - click/selection 변경 시에는 overlay canvas의 선택 ring만 clear/draw.
  - 결과: 2D click은 더 이상 5,000 edges/1,500 nodes 전체를 다시 지우고 그리지 않는다.
- `apps/legal-graph-chat/frontend/src/components/WebGLGraph.tsx`
  - 일반 ForceGraph node click/search에서도 같은 node 재선택은 parent callback을 호출하지 않도록 guard 추가.
- `apps/legal-graph-chat/frontend/src/styles/app.css`
  - graph viewport를 `position: relative`로 고정해 selection card absolute positioning scope를 graph 내부로 제한.
  - 2D canvas stack layout 추가.

### 검증 결과
- Frontend: `npm run typecheck` → 통과.
- Frontend: `npm run test && npm run build` → 통과 (`4 files / 20 tests passed`).
- Browser 3D static click instrumentation:
  - click 후 selected node 갱신됨.
  - MutationObserver 결과: `canvas-added/removed` event `0`.
  - 즉 WebGL canvas remount 없음.
- Browser 2D Canvas click instrumentation:
  - 실제 node click 후 selected node 갱신됨.
  - MutationObserver 결과: `canvas-added/removed` event `0`.
  - patched canvas width/height setter event `0`.
  - canvas는 base + overlay 2개 유지.
- Screenshot: `output/playwright/full3d-2d-3d-click-no-remount.png`
- Playwright console warning/error: `0`

### 최종 상태
- 클릭은 이제 “대형 그래프 전체 renderer 재생성”이 아니라 “선택 highlight만 갱신”한다.
- 3D static renderer는 click마다 scene/renderer/canvas를 재생성하지 않는다.
- 2D renderer는 click마다 base graph 전체를 clear/redraw하지 않는다.

## Phase 13. Flash-safe click pipeline 추가 대책

### 사용자 재피드백
- “계속 발생해 대책을 내놔봐”

### 추가 원인 후보와 대책
- Phase 12에서 canvas/WebGL remount는 제거됐지만, 클릭 후 App-wide state update가 여전히 남아 있었다.
- `loadNodeExplain`이 `loading="explain"`을 세팅/해제해 그래프와 무관한 전역 App re-render를 2회 추가 발생시켰다. Full 3D에서는 이 loading state가 화면에 직접 쓰이지 않으므로 불필요했다.
- Full 3D node click에서도 `/explain` 응답의 subgraph를 `setSubgraph`로 갱신하고 있었다. Full 3D 화면에서는 필요한 데이터가 inspector summary/source인데, subgraph 갱신은 다른 tab용 상태를 건드려 추가 re-render와 메모리 churn을 유발했다.
- 선택 card의 `backdrop-filter: blur(12px)`는 canvas 위에서 브라우저 compositor가 큰 영역을 재합성하게 만들 수 있어, canvas remount가 없어도 “번쩍”처럼 보일 수 있다.

### 적용한 수정
- `apps/legal-graph-chat/frontend/src/App.tsx`
  - `loadNodeExplain(node, { updateSubgraph })` 옵션 추가.
  - Full 3D click은 `updateSubgraph: false`로 호출해 graph tab 외 상태 갱신 차단.
  - `loading="explain"` 전역 state set/clear 제거. `/explain` 요청은 그대로 유지하되 그래프 영역을 재렌더링시키는 전역 loading 변경을 없앴다.
  - 같은 node 선택 시 `selectedNodeId` setter는 기존 값을 유지하도록 no-op 처리.
- `apps/legal-graph-chat/frontend/src/styles/app.css`
  - graph viewport/canvas stack에 `isolation`/`contain`/GPU layer hint 추가.
  - `.lg-webgl-selection`의 `backdrop-filter` 제거. 선택 card는 opaque background로 변경.

### 검증 결과
- Frontend: `npm run typecheck && npm run test && npm run build` → 통과 (`4 files / 20 tests passed`).
- Browser 3D click instrumentation: selected node 갱신, `canvas-added/removed` event `0`.
- Browser 2D click instrumentation: selected node 갱신, `canvas-added/removed` event `0`, canvas width/height setter event `0`.
- Playwright console warning/error: `0`.

### 다음 강제 대책
- 만약 사용 환경에서 여전히 flash가 보이면, 다음 단계는 “클릭 시 inspector 자동 fetch”를 완전히 분리하는 `Graph click safe mode`다.
- safe mode에서는 graph click이 local highlight만 즉시 바꾸고, inspector fetch는 200~300ms debounce 후 별도 low-priority task로 실행한다.
- 그 다음에도 남으면 선택 card를 graph 위에 띄우지 않고 inspector pane에만 표시해 canvas 위 compositor repaint를 완전히 제거한다.
