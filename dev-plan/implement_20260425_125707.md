# implement_20260425_125707.md

작성 일시: `2026-04-25 12:57:07 KST`

이 문서는 Full 3D raw static graph가 화면에서 회색 덩어리처럼 보이는 문제를 root cause 기반으로 수정하고, 이후 대용량 payload 최적화 후보를 단계적으로 진행하기 위한 작업 문서다.

## 개발 목적
- `9,001 nodes / 176,128 edges` Full 3D raw static renderer가 구조를 읽을 수 있는 3D 조망으로 보이게 한다.
- force simulation freeze를 재도입하지 않고, static BufferGeometry 경로를 유지한다.
- 대형 raw JSON 로딩/파싱 최적화 후보를 현재 구현 범위와 후속 범위로 분리한다.

## 개발 범위
- Root cause 확인:
  - browser smoke/screenshot으로 현재 현상을 재현한다.
  - static renderer의 camera, opacity, render order, centering 로직을 분석한다.
- Immediate fix:
  - all-edge 과밀 오버드로우를 줄이는 adaptive edge opacity를 적용한다.
  - edge와 node render order를 분리해 node가 edge slab에 덮이지 않게 한다.
  - backend 좌표의 X/Z 3D ring이 정면 카메라에서 2D로 눌리는 문제를 oblique 초기 view로 완화한다.
  - bounds center를 기준으로 buffer 좌표를 정규화해 그래프가 중앙에 안정적으로 보이게 한다.
- Test/verification:
  - static renderer 유틸에 회귀 테스트를 추가한다.
  - frontend typecheck/test/build와 browser screenshot smoke를 실행한다.
- Optimization plan:
  - backend static layout disk cache, binary payload, worker parsing, gzip/streaming, GPU picking의 우선순위를 문서화한다.

## 제외 범위
- 이번 즉시 수정에서는 binary graph protocol 전체 전환은 제외한다.
- GPU picking/label full parity 구현은 후속 Phase로 둔다.
- 법령 그래프 layout 알고리즘을 force/WASM layout으로 교체하지 않는다.
- raw all-edge를 react-force-graph-3d force simulation에 다시 넣지 않는다.

## Root cause hypothesis
- 현재 raw all-edge static renderer는 `176,128`개 edge를 opacity `0.13` 단일 회색 line으로 그린다.
- transparent line overdraw가 누적되어 화면 중앙이 거의 불투명한 회색 slab이 되고, node/community color가 묻힌다.
- points를 먼저 추가하고 lines를 나중에 추가해 edge가 node 위에 덮이는 시각 결과가 발생한다.
- backend static layout은 community를 X/Z ring에 배치하지만 camera가 `+Z` 정면에서 보므로 Z depth가 눌려 3D 구조가 2D 수평 덩어리처럼 보인다.

## 최종 구현 결과 (2026-04-25 13:04 KST)

### 원인 확정
- Playwright screenshot으로 raw all-edge가 회색 slab처럼 보이는 현상을 재현했다.
- 직접 원인은 `176,128`개 edge를 opacity `0.13` 단일 회색 line으로 렌더링하면서 transparent overdraw가 누적된 것이다.
- 추가 원인은 points보다 lines가 시각적으로 위에 그려져 node/community color가 묻히고, 초기 camera가 `+Z` 정면이라 backend X/Z ring layout이 납작하게 투영된 것이다.

### 구현 요약
- `staticGraphRenderer` 유틸을 추가해 raw edge count별 opacity, node point size, bounds centering, oblique camera position을 테스트 가능하게 분리했다.
- `StaticBufferGraph`가 backend 좌표를 bounds center 기준으로 정규화하고, 초기 oblique view로 시작하도록 변경했다.
- edge opacity를 raw 176k 기준 `0.0035`로 낮춰 과밀 edge를 slab이 아니라 faint density haze로 보이게 했다.
- edge를 먼저, node를 나중에 렌더링하고 node material을 `depthTest=false`로 설정해 community color가 edge에 묻히지 않게 했다.
- wheel zoom은 camera vector length를 조정하도록 바꿔 oblique camera에서도 줌 방향이 안정적으로 유지되게 했다.

### 후속 최적화 우선순위
- P1: WebWorker parsing — raw JSON parse가 main thread를 막는 시간을 줄이는 효과가 가장 큼.
- P1: backend static layout disk cache — layout 재계산 제거와 cold-start 안정화. 단, 현재 병목은 주로 payload 직렬화/전송/parse다.
- P2: streaming/binary payload — 효과는 크지만 API contract와 worker/parser 변경 범위가 커서 별도 Phase가 적합하다.
- P2: GPU picking/labels — static renderer interaction parity 개선용. visual/perf 안정화 이후 진행한다.
- 참고: backend `GZipMiddleware`는 이미 적용되어 있으므로 gzip 기본 대응은 현재 상태에서 충족한다.

### 잔여 리스크
- raw all-edge는 구조 조망용 density view이며, 개별 edge 판독은 focus/subgraph/evidence view에서 처리하는 것이 맞다.
- 176k edge를 모두 보이게 하면 어떤 renderer에서도 hairball 특성은 남는다. 이번 수정은 freeze 제거 + slab 완화 + node 가시성 복구에 집중했다.
